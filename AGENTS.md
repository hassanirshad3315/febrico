# FABRICO AntiGravity Engineering Agent Instructions

## 0. Mission

You are the primary development agent responsible for continuing the FABRICO luxury women's fashion e-commerce project from the exact state in which the previous website-building agent stopped.

Your job is NOT to restart the project, redesign it from scratch, or create a separate prototype.

Your job is to:

1. Inspect the existing repository and determine the current implementation state.
2. Read `README.md` completely before changing application code. The README contains the product requirements/master website prompt.
3. Read `log.txt` before starting work and continue from the latest recorded state.
4. Preserve completed work unless it is demonstrably broken or conflicts with the requirements in `README.md`.
5. Replace/remove obsolete Lovable-specific authorization, runtime dependencies, redirects, branding, environment assumptions, or generated integration code that prevents the project from running independently under AntiGravity/local development.
6. Continue implementation from where the previous agent left off.
7. Keep the application functional after every meaningful change.
8. Record every meaningful work session in `log.txt` so another agent can continue without reconstructing history.

Treat `README.md` as the canonical product specification and `log.txt` as the canonical implementation handoff history.

## 6. Engineering standards

### General

Write maintainable production-quality code.

Prefer small reusable components over giant files.

Use strong typing where TypeScript is available.

Keep business logic outside presentation components where practical.

Do not duplicate logic.

Do not hardcode data that belongs in the database or CMS.

Do not hardcode the WhatsApp number.

Do not hardcode trending/bestseller rankings.

### Database

Use proper relationships, indexes, constraints, and validation.

Do not introduce duplicate tables merely because existing tables are unfamiliar.

First inspect the current schema.

### Security

Never expose service-role keys, private keys, or secrets in client-side code.

Do not disable authorization checks to solve development problems.

Use server-side authorization where applicable.

Do not expose private customer information through public routes.

### Frontend

Maintain responsive behavior at:

320px, 375px, 390px, 480px, 768px, 1024px, 1280px, 1440px, 1920px.

Avoid horizontal overflow.

Maintain consistent typography, spacing, and component behavior.

### UX

Every major user action must have:

- Loading state
- Success state where relevant
- Error state
- Empty state where relevant

Never leave a user staring at a broken or blank interface.

## 7. FABRICO visual direction

The storefront should look like a premium fashion editorial experience.

Use:

- Near-black
- Warm ivory
- Cream
- Stone
- Taupe
- Restrained champagne/gold

Use gold sparingly.

Typography:

- Editorial serif for major fashion headlines
- Clean modern sans-serif for UI and product information

Prefer photography-led layouts, generous whitespace, refined typography, restrained shadows, and sophisticated motion.

Avoid:

- Generic SaaS appearance
- Purple AI gradients
- Neon colors
- Excessive glassmorphism
- Excessive rounded cards
- Excessive shadows
- Bouncy animations
- Overcrowded product grids

The homepage should alternate merchandising and storytelling rather than becoming a continuous wall of product cards.
